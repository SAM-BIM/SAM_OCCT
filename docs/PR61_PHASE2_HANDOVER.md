## Blocker A (Phase 1) — cap holes: `InRange` ignores internal openings

**Sol's finding:** current B2 Case A uses `Face3D.InRange`, which tests only the OUTER loop and
ignores holes. A wall sample under an atrium/opening is treated as physically covered → Case A →
accepted at unlimited vertical distance.

### Confirmed API behaviour (source: `..\SAM\SAM\SAM.Geometry\Geometry\Spatial\Classes\Face3D.cs`)

- `Face3D.InRange(p, tol)` (line 236): `plane.On(p,tol)` gate, then
  `externalEdge2D.InRange(p2D, tol)` = On-OR-Inside the OUTER ring, boundary-INCLUSIVE, **holes
  IGNORED**. ← the hole-blind method the current code calls (`Panel3DSnapSolver.cs:2700`).
- `Face3D.Inside(p, tol)` (line 210): outer `Inside` (boundary-EXCLUSIVE) AND `!hole.Inside` for every
  hole. Hole-aware but excludes the outer edge — would break neighbour tiles whose edge meets the wall.
- `Face3D.On(p, tol)` (line 244): outer `externalEdge2D.InRange(p2D)` (boundary-INCLUSIVE) AND
  `internalEdge2Ds.TrueForAll(h => !h.Inside(p2D, tol))`. = "point lies on the cap's actual material,
  including the outer boundary, excluding holes." **This is the drop-in hole-aware replacement.**
  - Quirk: the outer `InRange` call does NOT forward `tol` (uses `Core.Tolerance.Distance`). In
    `NearestCoveringCap` the passed `toleranceDistance` is `Tolerance.Distance` (1e-6) anyway, so no
    effective difference — but note it if the caller ever passes a larger tol.
  - Hole-boundary behaviour (Phase 1 test D): a point exactly on a hole edge → `hole.Inside` is false
    (edge-exclusive) → `On` returns TRUE (edge counts as material). A point `tol` inside the hole →
    `hole.Inside` true → `On` false. Deterministic.
- **No-holes equivalence:** when a cap has no internal edges, `Face3D.On` returns
  `externalEdge2D.InRange(p2D)` — identical to `InRange`. So swapping `InRange`→`On` is a **no-op for
  every current fixture cap** (towers / two-level / flat / tilted caps and the pitched-roof home
  fixtures are all hole-free) and only changes behaviour for caps that actually carry an opening. Zero
  golden/existing-test risk.

### Proposed smallest production change (`Panel3DSnapSolver.NearestCoveringCap`, line ~2700)

Replace:
```
bool contained = capFace3D.InRange(new Point3D(x, y, capZ), toleranceDistance);
```
with a hole-aware call:
```
bool contained = capFace3D.On(new Point3D(x, y, capZ), toleranceDistance);
```
(Verify `Face3D.On` is the intended predicate; if the tol-forwarding quirk is a concern, use an
explicit `InRange(outer) && no hole.Inside` — but `On` already encodes exactly that.)

### Proposed Case A / Case B semantics for a sample inside a hole

- Sample in solid cap material (incl. outer boundary, excl. holes) → **Case A**, valid at any gap.
- Sample inside a hole → **NOT Case A**. Remains eligible **only via Case B** (bounded continuation:
  `|capZ − wallExtreme| ≤ CAP_LOCAL_LEVEL_CONTINUATION` = 2.0 m). This directly fixes Sol's defect
  ("accepted at unlimited vertical distance" becomes "rejected when the cap is far"), and matches the
  requested test matrix (B = not Case A; C = inside opening + far cap → rejected). **User must confirm**
  this vs the stricter "a hole sample always rejects the cap."

### Proposed 5 hole regression tests (extend `WallCapSelectionTests`, drive production `Extend`)

Cap = a flat rectangle with an internal rectangular opening (use `Face3D` with an internal edge loop;
`TestGeometry.CreatePlanarFace` builds single loops — will likely need a helper that builds a
`Face3D` from an external loop + one internal loop, e.g. via `Face3D.Create(loops)` /
`Geometry.Spatial.Create.Face3D(externalClosedPlanar3D, internalClosedPlanar3Ds)` — confirm the
available ctor).
- **A** sample in solid material, cap within band → extends (Case A).
- **B** sample inside the opening, cap at small gap → NOT Case A; extends only if within Case B band.
- **C** sample inside the opening, cap far above (gap > 2.0 m) → rejected (no extend). *(This one
  fails at HEAD `331ca6b` — `InRange` accepts it — and passes after the `On` change.)*
- **D** sample on / just inside the opening boundary → deterministic tolerance behaviour (on-edge =
  covered; `tol` inside = not covered).
- **E** upward and downward variants of A/C.

**Compatibility note:** neighbour cap tiles and pitched roofs are unaffected (hole-free → `On` ≡
`InRange`). Confirm by re-running goldens + `Extend3DPlaneTargetIntegrationTests` after the change.
