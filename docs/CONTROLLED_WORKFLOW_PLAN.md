Build and validate the inspectable workflow:

```text
Panels

  → SAMOCCT.Extend3D            (inputAlreadyClean = true in this chain)
  → SAMOCCT.CreateAdjacencyCluster   (existing rebuild path)

```

Key adjustments over the first draft (from codex review, all verified against the repo):

1. **Exact stage chaining.** `Extend3D` currently runs Clean internally (`StopAfterExtend` executes `SnapStage.Clean` then `ConditionStage`). The chained workflow must not clean twice: add an explicit `inputAlreadyClean_` path (condition-only). P0 measures the current double-clean difference; P2 implements the handoff.
2. **Core/API compatibility with a practical GH default.** Core `bucketBetweenLevels = 0`, so unset library behavior stays byte-identical. GH components use the documented generic `0.21` default; larger fixture-specific values are explicit tuning, not global defaults. `inputAlreadyClean = false` and `directionalCapGrow = false` everywhere. The controlled fixture/example explicitly wires `0.21 / true / true`.
3. **GUID identity in validation.** `Space.Guid` is the validation identity; names are human-readable labels only. Duplicate/multiline names → warnings + disambiguated labels in the general component; the controlled fixture separately hard-requires nine distinct single-line names.
4. **Truthful observability.** Clean actions are recorded at their real decision points via an optional recorder (analogous to `ExtendRecord`) — never inferred post-hoc from geometry diffs. A null recorder is geometry-identical.
5. **Fail-closed directional cap growth.** In directional mode, missing evidence or reconstruction failure emits a skip record and grows nothing — no fallback to uniform whole-cap growth (that would reintroduce the false-floor risk). Legacy uniform growth remains only when the flag is off.
6. **Missing-wall honesty.** A genuinely absent separator cannot pass the nine-space acceptance gate. The original model is preserved as a diagnostic fixture; a corrected panel fixture is required for hard acceptance. Clean3D/Extend3D never invent faces.
7. **Existing architecture preserved.** No duplication or regression of `ResolvedCellComplex`, `CellComplexHandoff`/SolveId roster gating, E1–E3 Extend work, or adoption-gate hardening (merged as `065b02c`, PR #56). `CreateAdjacencyCluster` stays a lean builder; the controlled chain uses its rebuild path (supplying spaces prevents direct CellComplex handoff by design).

## 1. Diagnosis — why the current approach goes wrong

All claims verified in the current repo.

- **D1 — Level frames cannot merge (5-vs-3).** `LevelFrame.Cluster` is always called with the compile-time `DEFAULT_ElevationBand = 0.15` (`LevelFrame.cs:52`; call site `SnapStage.cs:143-148`). Fixture gaps 12.436−12.24 = 0.196 and 15.473−15.29 = 0.183 both exceed 0.15 → 5 frames. Nothing named `bucketBetweenLevels` exists in SAM_OCCT. GH `normalizeCapOffset_` (0.3) feeds only the zero-frames legacy fallback (`SnapStage.cs:158`). The 0.15 band is deliberate (protects ~0.25 m split-level landings) — so the fix is a second grouping stage, not a wider raw band.
- **D2 — Band exists but is not forwarded.** `AssignCapToFrame` already accepts `elevationBand` (`LevelFrame.cs:403-408`); today's callers (`ClassifyFace` at `LevelFrame.cs:586`, frame-aware `NormalizeCaps`) pass the compile-time default. A cap 0.196 m from a merged group datum fails membership and lands only via the nearest-datum ambiguity fallback. Fix = thread/forward the band, not new mechanics.
- **D3 — Extend targets un-merged planes.** Wall-to-cap extension (`Panel3DSnapSolver.Extend`, ~line 1742) collects cap planes from post-Stage-A panels; with 5 frames the 12.436/15.473 caps remain separate targets → walls stop at the wrong plane.
- **D4 — Uniform cap growth can fabricate a false floor.** `Fill` (~line 2030) → `SnappedPanel.GrowOutwardTo` offsets the whole cap boundary uniformly by the largest in-reach wall gap (+overshoot); a mid-level cap bordering a double-height void is pushed into the void → false intermediate floor → the double-height space splits at 15.29.
- **D5 — Silent extend decisions.** No skip records ("not extended and why"), no risk flags (near reach limit, blind growth, new overlaps).
- **D6 — Parameter precedence gaps.** `ResolveWeights` (`Solve.cs:690`) derives via SAM_Solver `SetWeights` on clones — a user-stamped `SolverParameter.Weight` is not guaranteed to win. `ResolveMaxExtends` (`Solve.cs:721`) falls back to constant 0.4 instead of `SetMaxExtends` derivation. `BucketSize` (`Solve.cs:746`) is correct (stamp → thickness-derived, floored at `minBucketSize`).
- **D7 — No expected-vs-actual validation.** `FindSeedSpace` (`AdjacencyCluster.cs:850`) silently skips a second seed landing in an already-claimed cell — exactly the "two expected spaces merged" signal, currently invisible.
- **D8 — Raw-first gates are coarse.** Watertight-but-wrong complexes can pass; GH users cannot see which panels were merged/extended/dropped. The controlled chain bypasses raw adoption (`StopAfterClean`/`StopAfterExtend` skip `TryRawResolve`), making every decision visible and tunable.
- **D9 — Fixture facts.** Panels model: 66 panels. Spaces model: re-exported with 9 distinct names, West3 confirmed as the double-height space (§0.1). The "MissingWalls" folder name suggests one or more separators may be genuinely absent from the input — P0 must prove present-but-unused vs absent.
- **D10 — The chained workflow double-cleans.** `Extend3D(Clean3D(panels))` runs `SnapStage.Clean` twice (once inside each call): second-pass snapping/normalization can move already-clean geometry, re-derive parameters, and rebuild source identity. Requires the explicit `inputAlreadyClean` condition-only path (P2) and a measured baseline of the difference (P0).

**Fixture ground truth (P0 re-verifies from the committed files):** north row (z≈13.9): North0 (1.89,−5.91), North1 (5.52,−5.72), North2 (9.18,−5.91); south group (z≈13.9): East1 (6.69,−20.48), South1 (6.50,−25.23), South2 (1.58,−23.46); **West3 (−4.14,−6.56, z=15.25, the double-height space)**; West1 (−4.14,−20.06, z=13.72); West2 (−4.14,−20.06, z=16.78). ## 2. Corrected architecture

```text
                 ┌─ per-panel overrides: SolverParameter stamps ("Bucket Size", "Weight", "Max Extend")
                 │  set via SAM_Solver's SolverProperties component; BuildPanels re-stamps outputs
                 ▼
Panels ──► Clean3D ──────────► Extend3D ─────────────► CreateAdjacencyCluster ──► ValidateSpaces
           organise & merge     inputAlreadyClean=true   rebuild path (sew +       GUID-matched report:
           (no fabrication)     condition-only           MakerVolume + seed        missing/merged/split/
           CleanReport          (no re-clean,            names); unchanged         extra by name label;
           LevelGroups          no fabrication)          component                 double-height; orphan/
           Panels→Visualize     ExtendReport+SKIP/RISKY                            unused panels; Valid
```

**Two-stage level grouping (central choice).** Raw `LevelFrame`s keep the pinned 0.15 band. A new second stage `LevelFrame.GroupFrames(frames, bucketBetweenLevels, …)` merges raw frames into `LevelGroup`s — dominant-area-first, seed-anchored, deterministic, non-transitive, membership by perpendicular datum distance (tilted levels supported). Cap normalization and extend targets work per **group datum**; wall bucket membership is never affected. `bucketBetweenLevels ≤ 0` → groups ≡ frames (identity). The raw `LevelFrames` view must keep producing five frames for the fixture; the grouped view produces three.

**Exact Clean → Extend handoff (`inputAlreadyClean`).** When true, `Extend3D`/`OpenPanels3D`: treat supplied panels as the exact Stage A result; build an identity source map; reuse stamped BucketSize/Weight/MaxExtend; cluster frames/groups **for reporting only** (no normalization, no cleaning); run `ConditionStage` directly; emit a coded diagnostic confirming Clean was skipped. When false (default), behavior is byte-identical to today.

**Semantic note (goes in the GH parameter description):** SAM_Solver's `bucketBetweenLevels` (GH default 0.21 there) is a final cross-level *wall re-snap*; here the same knob name controls *level-datum merging* (the user's intended meaning). Cross-level wall alignment stays out of scope (optional future Clean3D sub-pass).

**Stage guardrails:**
1. Clean3D: no geometry fabrication (no extends/fills/patches, no native kernel); panel-count changes only via recorded merges/drops; inputs never mutated; no space reasoning.
2. Extend3D: managed only — no MakerVolume/sew/trimming; grows only existing faces; **never invents faces** (GapFill stays exclusively in Solve3D); preserves holes.
3. Level grouping affects cap normalization and extend targets only — never wall bucket membership.
4. CreateAdjacencyCluster never re-runs conditioning; rebuild/`cellComplex_` handoff behavior preserved.
5. Every exclusion/skip/fallback emits a diagnostic — no new silent branch.

## 3. Parameters, precedence, defaults

| Parameter | Semantics (OCCT) | Core default | GH default | Controlled fixture | Per-panel override |
|---|---|---|---|---|---|
| BucketSize | perpendicular capture half-width, wall bucket snap | stamp → thickness×`thicknessFactor`, floored at `minBucketSize` | `minBucketSize_=0.4`, `thicknessFactor_=0.6` | defaults | `SolverParameter.BucketSize` ("Bucket Size") |
| Weight | backer priority in a bucket; caps dominate by area (dominant-area frame seeds + largest-area backer) | stamped → `SetWeights`-derived (length remap 0.2–1.0, air 0) → solver default | derived | defaults | `SolverParameter.Weight` ("Weight") |
| MaxExtend | lateral reach of wall extension (the 0.49×length cap belongs to the **lateral extension operation**, not to derivation) | stamped → `SetMaxExtends`-derived (0.33 unknown / 0.5 standard / 0.6 thick) → solver default (P3) | derived | defaults | `SolverParameter.MaxExtend` ("Max Extend") |
| bucketBetweenLevels | **new** level-group band over raw frames | **0 (off)** | **0.21** | **0.21** | none (global) |
| inputAlreadyClean | **new** condition-only Extend3D/OpenPanels3D mode | **false** | **false** | **true** | n/a |
| directionalCapGrow | **new** per-edge evidence-based cap growth | **false** | **false** | **true** | n/a |

**Precedence rule (guaranteed + unit-tested in P2/P3):** a valid per-panel stamp always wins; otherwise derive; otherwise solver default. Every resolved value carries a provenance tag in the CleanReport: `stamped | derived-length | derived-thickness | min-floor | default`.

**Override workflow (user-facing):** run with defaults → inspect CleanReport/ExtendReport → bake problem panels to Rhino → assign per-panel values with SAM_Solver's **SolverProperties** component → rerun Clean3D/Extend3D → visualize (`BuildPanels` re-stamps outputs at `Solve.cs:663-676`, so `SAMAnalytical.Visualize` draws capture slabs/reach at every stage). No positional `weights_`/`maxExtends_` list inputs on OCCT components — stamps are the one authoritative path.

## 4. Clean3D design (P2)

Keep: `StopAfterClean` → `SnapStage.Clean` = StripInternalEdges → SnapOpposedPartitions → SnapToFixedPoint (weighted bucket snap + AlignColinearOffset) → per-frame NormalizeCaps → coplanar Union. Raw `LevelFrame.Cluster` band 0.15 unchanged; `LevelFrameTests` pins unchanged.

Changes:
1. **`LevelGroup` + `GroupFrames`:** datum = dominant-area member frame; members joined by |perpendicular of member datum vs seed datum| ≤ band; carries frame indices, elevation, spread, dominant area, cap count. Fixture at 0.21: `12.240+12.436 → 12.240`, `15.290+15.473 → 15.290`, `18.340 → 18.340`.
2. **Band forwarding:** `effectiveBand = max(DEFAULT_ElevationBand, bucketBetweenLevels)`; forward through `NormalizeCaps` and `ClassifyFace` to `AssignCapToFrame`/`AssignWallToFrames` (`AssignCapToFrame` already accepts it — today's call sites pass the default). Normalize every claimed cap against the supplied **group datum plane exactly**, including a one-cap bucket; never reselect another cap plane after grouping.
3. **Plumbing:** GH `bucketBetweenLevels_` (default 0.21) → `Solve.cs` entry points (`Clean3D`/`Extend3D`/`Solve3D`/`OpenPanels3D`, trailing optional, core default 0) → `Panel3DSnapSolver.BucketBetweenLevels` → `SnapStage.Clean` → `GroupFrames`. `Solve3DReport.LevelGroups` + `SolverReportFormat.FormatLevelGroups`.
4. **`CleanRecord` recorder (instrumented, not diffed):** optional recorder threaded to the actual mutation sites; multiple records per source allowed; kinds `OpposedCollapsed | SnappedToBacker | CapNormalized | CoplanarMerged | DroppedInvalid | Preserved`; each record: source/backer identity, distance moved, level group, resolved parameter values, provenance. **A null recorder must be geometry-identical** (unit-tested).
5. **Near-miss diagnostics** at both cluster stages (`band < d ≤ 2×band`, capped at 20): states exactly what `bucketBetweenLevels` value would merge.

Diagnostic grammar:
```text
SAM_OCCT_CLEAN3D_LEVELS: 5 raw level frame(s) -> 3 level group(s) (bucketBetweenLevels=0.21 m).
SAM_OCCT_CLEAN3D_LEVELGROUP: group 0: elevation 12.240 m, frames [0,1] (12.240, 12.436), 15 cap(s), spread 0.196 m, tilt 0.0 deg
SAM_OCCT_CLEAN3D_PANEL: panel {guid} (#12) snapped-to-backer; moved 0.062 m onto {backerGuid} (#7); bucket 0.400 (min-floor); weight 0.74 (derived-length); maxExtend 0.50 (stamped); group 1
SAM_OCCT_CLEAN3D_DIAGNOSTIC: [Snap/LevelBandNearMiss/Info] cap 0.196 m from group 0 datum (band 0.150) - excluded; raise bucketBetweenLevels to >= 0.196 to merge.
```

## 5. Extend3D design (P2 handoff, P3 behavior)

Keep: `ConditionStage` order = wall-to-wall (`ExtendWalls`) → wall-to-cap (`Extend`, cap-scalar/cap-plane targets) → cap grow (`Fill`). Applied `SAM_OCCT_EXTEND3D_PANEL:` grammar **frozen**.

1. **`inputAlreadyClean` condition-only path (P2):** per §2. Also threaded into `OpenPanels3D`. Legacy path (`false`) proven byte-identical.
2. **Merged-plane targeting (P3):** with grouped normalization, `Extend`'s cap planes are the group datums; integration test proves walls extend to 12.24/15.29/18.34, never 12.436/15.473; Clean-side warning when a group's members still span > tolerance after normalization.
3. **Directional cap growth (P3, `directionalCapGrow = true`):** in the cap plane, per straight outer edge: outward direction → intersect candidate wall planes with the cap plane → require the wall line parallel within angular tolerance AND overlapping the edge span → nearest positive outward target within `fillMargin` → move only that edge by its measured gap + overshoot. **No facing wall in reach → edge grows 0.** Preserve holes; validate the reconstructed loop (validity, self-intersection, area increased). **Fail closed:** reconstruction failure or missing evidence → skip record, no growth, never uniform fallback. Legacy uniform growth only when the flag is false.
4. **Skip reasons (real branches, P3):** `NoTargetInReach | AlreadyAtTarget | NoFacingWall | DegenerateGeometry | ReconstructionFailed | ExtensionSolverFailed | OffsetBelowTolerance` → `SAM_OCCT_EXTEND3D_SKIP:` lines.
5. **Risk flags (metadata, not skips, P3):** `NearReachLimit | MaxExtendLimited | LengthRatioLimited | NewCoplanarOverlap | LegacyUniformCapGrow` → `SAM_OCCT_EXTEND3D_RISKY:` lines.
6. **MaxExtend derivation (P3):** unstamped fallback switches from const 0.4 to `SetMaxExtends` clone derivation (stamped values still win; no 0.49×length pre-cap in derivation — the solver's `EXTENSION_LIMIT_LENGTH_RATIO` applies at the lateral operation).

```text
SAM_OCCT_EXTEND3D_SKIP: panel {guid} (#3) top: NoTargetInReach (nearest cap 0.62 m above reach 0.40)
SAM_OCCT_EXTEND3D_RISKY: panel {guid} (#5) plan-end: NearReachLimit (used 0.38 of 0.40)
```

## 6. ValidateSpaces design (P1)

**Identity:** `Space.Guid` internally; names are report labels. Duplicate/multiline names → warnings + disambiguated labels (`West3#2`) in the general component; the controlled fixture hard-requires nine distinct single-line names (P0 gate).

**Core API** (new, pure managed, under `SAM_OCCT/SAM.Analytical.OCCT.Solver/`): `Enums/SpaceMatchOutcome.cs` (`Matched, Merged, Missing, Split, IncorrectlyBounded, Extra`); `Classes/SpaceMatchOptions.cs` (`Tolerance`, `SilverSpacing`, `LevelBand=0.21`, `LevelGroupBand=0.21`, `MinSplitPlanOverlap=0.5`, `LateralMargin=0.5`); `ExpectedSpaceSet.cs` (GUID-keyed; level groups inferred from input-panel caps via `LevelFrame.Cluster` + 1-D merge — self-contained, independent of P2 plumbing; `ToSeedSpaces()`); `CellGeometry.cs` (`FromCluster` via `GetShells()`, `FromComplex` via `OcctCell`); `SpaceMatcher.cs`; `SpaceMatchRecord.cs`; `CellMatchRecord.cs`; `SpaceMatchReport.cs` (`Valid`, `ToLines()`); `SeparatorPanelFinder.cs`; `PanelContributionFinder.cs`.

**Matching:**
1. Containment matrix with the builder predicate: `Shell.Inside(location, fuzzyTolerance, tolerance) || Shell.On(location, tolerance)` (mirrors `FindSeedSpace`).
2. Boundary ambiguity → nearest cell centre, then stable cell index; `BOUNDARY` warning line.
3. Classify expected: **Missing** (no cell; nearest cell + distance) · **Merged** (≥2 expected in one cell; partners) · **Matched** (sole occupant, span consistent) · **Split** (sole occupant, span fails, partner cells — no-expected cells with plan-bbox overlap ≥ `MinSplitPlanOverlap` of the smaller inside the expected span — exist; `SplitElevation` snapped to the nearest datum) · **IncorrectlyBounded** (span mismatch, no partner) · leftover cells → **Extra**.
4. Ordinary expected vertical spans inferred from grouped level datums; **double-height expectations only from `doubleHeightSpaces_`** (GUID-backed) — never inferred from a location (the fixture's double-height location sits 0.04 m from a datum; inference is unsafe; matcher emits an "ambiguous vertical assignment" info for any location within `LevelBand` of a datum).
5. Double-height pass = cell spans bottom and roof groups AND no near-horizontal boundary of that cell within `LevelBand` of an intermediate datum (15.29) inside its plan footprint; violation → Split with `"Unexpected split: <label> split at level 15.29"`.

**Panel contribution (two distinct checks):**
- `OrphanClusterPanels` — generated cluster panels related to zero spaces (`cluster.GetSpaces(panel)` empty).
- `UnusedInputPanels` — supplied source panels with no coplanar overlapping contribution to any generated cluster face (geometric test — the builder fabricates new panel identities, so `GetSpaces(inputPanel)` cannot measure contribution).

**Missing-separator analysis (on source panels):** for each merged pair, scan supplied panels for a vertical separator between the two locations (plane strictly between — signed offsets opposite; lateral coverage — projected midpoint inside the face, bbox+`LateralMargin` → "partial"; vertical coverage of both z's). Report: candidate exists but unused / partial candidate / genuinely absent.

**`Valid` is true only when:** no Missing, Merged, Split, or IncorrectlyBounded expected spaces; no Extra cells; all requested double-height checks pass; no OrphanClusterPanels. Unused or merged-away source panels are warnings unless one should separate a merged pair.

**GH component `SAMOCCTValidateSpaces`** (v1.0.0, `GH_SAMVariableOutputParameterComponent`, SAM/OCCT): inputs `_adjacencyCluster`, `_expectedSpaces`, `sourcePanels_` (optional), `doubleHeightSpaces_` (optional Space list), `levelBand_` (0.21), `bucketBetweenLevels_` (0.21), `_run`. Binding outputs `Report`, `Valid`. Voluntary: `MatchedSpaces`, `MissingSpaces`, `MergedSpaces`, `SplitSpaces`, `IncorrectlyBoundedSpaces`, `ExtraShells`, `SuspectedSeparatorPanels`, `OrphanClusterPanels`, `UnusedInputPanels`, `DoubleHeightOk`, `CellMatches`.

## 12. Risks

1. **Compatibility** — core/API behavior remains off/byte-identical; GH components default `bucketBetweenLevels_` to 0.21. Default-core goldens + Extend3D regression fixtures stay frozen, and the 0.21 managed variant is pinned separately with its mechanism documented.
2. **Fail-closed directional growth** — caps may not close where wall evidence is missing; that is intended visibility (skip records point at the gap), but it means the fixture may need per-panel tuning or a corrected model rather than silent uniform growth.
3. **Over-merge at large bands** — `bucketBetweenLevels ≥ 0.25` can eat a split-level landing; warn at ≥ 0.25; near-miss lines always explain.
4. **Seed-anchored non-transitivity** — chained caps > band from the dominant seed stay separate (by design); near-miss lines make it visible.
5. **Boundary locations** — expected locations near shared walls can flip cells on millimetre shifts; deterministic tie-break + BOUNDARY lines + nearest-distance reporting.
6. **Double-height designation (resolved 2026-07-10)** — West3 confirmed as the double-height space (§0.1); acceptance still keys on the GUID captured at P0, not the name string.
7. **Genuinely missing separator (P0-dependent)** — hard acceptance then requires a corrected fixture; the original stays a pinned diagnostic fixture. No invented geometry.
8. **Double-Clean delta (P0-dependent)** — the measured difference between the two extend paths defines what `inputAlreadyClean` must reproduce; if the delta is zero the mode is still required (it removes re-derivation and identity churn) but its parity proof is easier.
9. **`two-level-tilted` managed baseline instability** — stabilize/pin before P3 re-verification.
10. **Sequential phases** — P2 → P3 dependency (grouped datums before extend targeting); do not parallelize branches.
